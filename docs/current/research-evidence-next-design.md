# 灾害应急矢量融合研究下一步工作计划

> 状态：A1 当前执行计划
> 更新日期：2026-09-07
> 研究主线：证明知识图谱与大模型协作能否比合理基线更准确、更及时、更可靠地完成灾害应急矢量数据融合

## 当前批准设计（2026-09-08）

本节覆盖下文历史执行顺序，原实验和失败不覆盖、不混池。主线是**证明 KG+LLM 相对公平、可运行基线的优越性**，不是停止路线，也不是通过削弱基线、挑选已答对案例或事后更换指标制造优势。本次更新不代表新增实验已经执行。

### 原因与方法假设

- 9 月 7 日四个融合组产生相同道路数量和端点 proxy，KG+LLM 未提出有效恢复动作；LLM-only 又受到公共接口和适配器阻塞。不能把接口失败解释为 KG 增益。
- 9 月 5 日 Full KG 排序正确为 120/120，但故障决策为 40/120，LLM-only 为 43/120；局部排序收益没有转化为普遍故障处置能力。严格主指标与事后语义指标分别报告。
- 道路端点 proxy 对分段敏感，旧质量拒绝保留；新增共同独立评价，不修改旧阈值使任何组获胜。
- 待验证机制：KG 提供来源、算法、质量与恢复约束，LLM 根据请求和实际反馈组合可执行动作，提高资源受限任务的截止前达标交付率。状态条件子图与有限反馈重规划是候选方法，不是已证最优方法。

### 下一验收点与开发矩阵

先修复 LLM-only 适配器并验证真实规划来源，禁止隐藏 fallback；补共同质量评价；用 trace 确认至少一种恢复动作真正改变执行器来源、参数或操作，并产生相应执行结果。只改计划文字或 revision 不算动作变化。不新增平台、冻结分支或外部审查前置。

随后执行 4 条件 x 5 方法 = 20 次开发筛查，每单元一次，不宣称统计显著性：

| 条件 | 真实决策机会 | 验证对象 |
| --- | --- | --- |
| 正常、多源可用 | 常规融合 | 基线可运行、质量与额外开销；允许打平 |
| 多图层、紧迫时限 | 产品顺序、慢源等待、部分交付 | 预算与依赖约束下调度 |
| 主源延迟或中断 | 等待、换源、重新材料化 | 观测驱动恢复 |
| 首次质量失败 | 有效修复、替代来源或明确降级 | 质量反馈后的可执行决策 |

复用 C02/C04/C06 类真实资产；每个困难实例须事先确认存在可行方案，所有方法共享其动作权限。条件由应急需求和来源特性确定，不按 Full KG 已经获胜的案例筛选。受控故障标记为注入，不冒充自然失败。无可行方案的案例另作安全诊断，不混入可交付机会分母。

### 基线与评价

五组为 fixed、rules、LLM-only、KG-only、KG+LLM。Fixed 为工程下限；Rules 有通用预算、重试、换源和部分交付策略；KG-only 使用同知识确定性约束选择，不以首候选选择器充当正式基线。LLM-only 获得完整公共来源元数据、工具参数说明和执行反馈。“正常运行”指接口完备、合法动作能执行，不保证困难案例必然成功。

共享数据、候选动作、执行器、安全门、计算资源和外部网络轨迹；模型组同模型、调用/token 上限与重试规则，禁止预读未来故障。输入准备开销单列；任务计时包含解析、检索、模型、下载、融合、评价和发布。缓存运行、受控网络和外网下载分开标记。

主指标为截止前达标交付率，完整与部分交付分开报告，正确拒绝不算完成融合。共同评价报告真实产品质量、错误发布率、首个可用成果时间、总耗时、模型/KG 开销和实际 token。道路评价覆盖分段不变性、端点接在线中部、合理尽端与立交不误连；无独立核验标签时只称诊断指标，不称真实精度。

20 次筛查仅定位差异与失败机制。正式确认使用未调试 AOI、任务组合和故障轨迹；最低有意义增益、主比较对象、分母、deadline、阈值和预算在确认前记录。样本量依据开发集波动与目标增益安排，按案例/场景处理相关性，重复调用不充当独立样本，不根据途中胜负选择性停止或追加。

### 协作与知识归因

同案例和预算比较静态 KG+LLM、状态条件子图+LLM、再加入反馈重规划；随后逐项移除来源、能力参数、契约质量、资源恢复等知识，保留共同安全约束。增加同事实平铺文本+LLM 后才可判断图结构/查询机制贡献，未完成时不得声称图结构本身优于文本。

仍采用相同动作或共同不达标时，先报告执行链和失败原因、修复真实机制，不扩大无区分度批次。改变研究目标、评价语义或预算的计划外扩展需重新确认。

## 1. 计划目的

本计划不再把“是否继续研究路线”作为首要决策，也不把 planning-only 结果当作最终任务结果。当前要做的是在既定 KG+LLM 主线上，快速获得一轮能对应真实任务的比较证据，并据此优化 KG 与 LLM 的结合机制。

完整任务链固定为：

```text
任务解析（灾种、区域、产品和时限）
  -> 数据源检索与下载
  -> 任务规划与资源调度
  -> 矢量融合执行
  -> 结果质量审查
  -> 重试、降级、部分交付或发布
```

每个方法都必须在同一执行链上比较。方法只改变其允许的知识、规划和恢复决策，不得通过不同的算法、数据、执行资源或评价规则获得额外优势。

### 3.3 比较方法

第一轮使用以下五组，保证每组都能完成相同闭环：

## 4. KG 与 LLM 的候选协作机制

第一轮优先实现并比较下列机制，而不是继续扩大知识类数量：

| 机制 | KG 输出 | LLM 作用 | 主要假设 |
| --- | --- | --- | --- |
| 全量注入 | 当前任务相关的完整 KG 投影 | 一次性生成计划 | 简单，但上下文冗余和干扰较大 |
| 状态条件子图 | 按灾种、AOI、产品、来源状态、时限和已发生故障检索子图 | 生成当前阶段动作和备选动作 | 信息更集中，适合第一候选方案 |
| 执行反馈重规划 | 初始子图 + 下载/质量/网络观测后的增量子图 | 选择等待、替代、降级、重试或发布 | 最能检验应急动态适应能力，但调用和时延更高 |

推荐的主方案是**状态条件子图 + 执行反馈触发的有限次重规划**：

- KG 保存稳定语义：灾种、任务、区域解析规则、来源能力、算法适用条件、质量门、时限策略、恢复策略和历史证据。
- 运行时观测保存动态事实：下载是否成功、当前带宽、剩余时间、来源是否可用、质量门结果和已生成产物。
- LLM 只提出候选动作与理由，不创造来源、算法或质量结论。
- 确定性层检查来源和算法 grounding、依赖、时间预算、契约和质量结果，再执行或拒绝。
- 每次重规划只能使用当时已经发生或可观测的状态，不提前读取未来网络故障。

## 5. 评价指标

### 主指标

- 截止时间前交付达标融合成果的任务比例。

### 次指标

- 任务解析正确率：灾种、AOI、产品和时限。
- 首个可用成果时间、完整成果时间、总耗时和 LLM/KG 额外开销。
- 实际下载成功率、有效来源选择率、重试成功率和恢复成功率。
- 结果质量：几何有效性、AOI 覆盖、道路重复率/连通性、建筑几何与属性、面水覆盖、POI 去重等任务特定指标。
- 交付状态正确率：`full`、`partial`、`provisional`、`degraded`、`gap`、`manual_intervention`、`reject`。
- 错误接受率：质量不合格或来源不合法的结果被错误发布的比例。
- 证据完整性：原始失败、来源、算法、质量报告、重试关系和 supersession 是否可追溯。

完整交付、合理部分交付、安全拒绝和正确缺口声明分开统计。不能把“拒绝了任务”与“完成了融合”合并成一个成功率。

### 时间与网络实验语义

- 从任务解析开始计时，包含 KG 检索、LLM 调用、下载、融合、质量审查和发布。
- 使用可控的本地 source server 或网络代理注入限速、延迟、断连和恢复，记录实际字节、带宽、失败时刻和重试等待。
- 各方法经历同一外部网络轨迹，但不能提前看到故障序列。
- deadline、来源状态和质量结果属于运行输入/观测，不写入 gold 或未来状态。

## 6. 第二阶段：知识内容贡献消融

在第一阶段闭环能运行后，保持同一任务、数据、算法和网络轨迹，只逐项移除以下知识族：

1. 任务与实体语义：灾种、AOI、产品别名和 canonical mapping。
2. 来源与算法能力：输入输出类型、适用任务、覆盖范围、质量和成本。
3. 产品契约与质量门：必需字段、几何/拓扑/属性检查和发布条件。
4. 时限与恢复策略：优先级、并行/顺序、替代来源、重试、降级和 supersession。
5. 证据与经验：来源溯源、失败类别、历史成功率和恢复经验。

消融必须保持其余知识可用，不能因删除 ontology 同时删除 capability 和 contract。每类知识应安排能触发其作用的案例，并按正常、紧急、波动和组合条件分层报告。
