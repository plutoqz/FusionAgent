# FusionAgent 研究章程

> 状态：P0-R 已验收，A0 当前权威研究基线  
> 版本：1.0.0  
> 冻结日期：2026-07-28  
> 适用范围：硕士论文、首篇期刊论文、知识图谱建设与后续实验

## 1. 研究定位

FusionAgent 的研究主体是**面向灾害应急多源地理空间融合的契约化知识图谱及其受约束规划方法**。产品契约、数据源语义、算法能力、质量门、降级恢复、证据链和缺口声明不是相互独立的功能，而是灾害知识图谱中共同约束数据产品生成与交付的知识对象。

核心主张冻结为：

> 在限定灾害案例和 AOI 范围内，契约化灾害知识图谱能够统一表达灾害情景、数据产品需求、数据源语义、算法能力、质量约束、降级策略和证据要求，并通过知识约束规划提高多源地理空间融合任务的可执行性、可恢复性与可审计性，同时保持任务特定融合质量的可复现性。

该主张包含两项不可拆分的要求：

1. 知识图谱必须是规划与治理行为的实际决策依据，而不是运行结果的附属展示。
2. 任何有效性结论必须由基线、消融、重复实验和冻结证据支持，不能由功能数量或测试通过数替代。

## 2. 研究对象与问题边界

### 2.1 研究对象

研究对象是灾害应急场景下，从用户请求或灾害事件到多源地理空间数据产品交付的完整知识与执行链：

```text
灾害情景
  -> 数据产品契约
  -> 数据需求与数据源语义
  -> 数据-算法-任务能力
  -> 受约束规划
  -> 执行与质量校验
  -> 证据、缺口与经验回写
```

当前验证任务限定为建筑物、道路、水体面、水系线和兴趣点等已有融合能力；案例和 AOI 的外部推广边界必须在实验中明确说明。

### 2.2 不属于主要研究对象的内容

- 底层融合算法本身的原创性。
- 通用灾情研判或应急指挥决策。
- 不受约束的通用 LLM Agent。
- 生产级、多租户或大规模分布式平台能力。
- 覆盖所有城市、灾种、数据源和地理产品的普遍性结论。

## 3. 研究目标

### O1：冻结统一、可计算的灾害知识图谱

将散落在 seed、schema、服务函数、策略常量和实验配置中的领域知识迁移到同一版本化知识基线，形成模式层、实体层、关系层、约束层和来源记录完整的 KG v1。

### O2：证明知识图谱实际驱动系统行为

规划、任务编译、质量验收、数据源替代和恢复决策必须引用 KG 中的稳定实体或策略标识。修改 KG 中的约束后，系统行为应在不修改执行代码的条件下发生可解释变化；缺少必要知识时应 fail closed。

### O3：评价 KG 约束规划的增量价值

通过固定工作流、规则策略、KG-only、LLM-only、LLM + capability KG 和 LLM + full contract KG 等对照，评价计划有效率、契约满足率、错误结果接受率、人工干预量和规划代价。

### O4：评价治理、恢复与复现能力

在限定案例、AOI、故障条件和重复运行下，评价质量门、渐进式交付、降级恢复、证据完整性和语义稳定性。

## 4. 研究问题

| 编号 | 研究问题 | 主要比较 | 核心证据 |
| --- | --- | --- | --- |
| RQ1 | 契约化七层知识图谱能否完整、一致地表达灾害数据产品生成所需的情景、需求、能力、质量、恢复与证据知识？ | 分散知识基线、能力目录型 KG | competency questions、约束校验、知识片段闭合率 |
| RQ2 | 知识图谱是否真正决定任务编译、候选检索、质量验收和恢复行为？ | KG 驱动、隐藏硬编码或固定工作流 | 行为扰动测试、缺失知识 fail-closed 测试、决策溯源 |
| RQ3 | KG 约束规划是否比固定规则、KG-only 或 LLM-only 产生更多可执行且满足产品契约的计划？ | 多种规划配置 | pre-fallback validity、契约满足率、无效计划率、规划代价 |
| RQ4 | 产品契约、质量门与知识化恢复策略是否改善受限案例中的交付、恢复和审计结果，并保持融合质量可复现？ | 无契约、无质量门、无 healing、完整方法 | 成功率、错误接受率、恢复率、时间、质量损失、证据完整率、语义哈希 |

首篇期刊论文可根据证据成熟度选择 RQ1–RQ3，或选择 RQ1、RQ2、RQ4 的受限组合；不得在实验完成前预设显著性结论。硕士论文覆盖完整四问。

## 5. 创新点

### I1：面向灾害应急数据产品的契约化七层知识图谱

构建连接灾害情景、产品契约、数据需求、数据源语义、算法任务能力、规划决策、执行质量及证据经验的统一知识模型，使质量、降级和证据要求从运行代码中的隐含规则转化为可查询、可验证、可版本化的知识对象。

### I2：知识约束的规划与确定性接地机制

将规划器限定在 KG 给出的候选能力、产品约束、资源处境和历史证据空间中，并由确定性 validator 检查类型、依赖、参数、契约和运行能力。LLM 的角色是受约束的候选计划提议者，而不是知识真源或最终验收者。

### I3：质量与证据驱动的闭环恢复机制

将质量门结果、故障类型、可接受降级、修复策略、缺口声明和 supersession 关系纳入同一知识与证据链，使失败暴露、恢复选择和最终交付可追溯，并能够沉淀为后续规划可检索的经验。

### I4：面向知识驱动系统的可复现实验证据方法

对 KG 版本、输入、prepared input、规划、输出、质量报告和证据清单统一冻结，以语义稳定哈希和独立验证器区分运行元数据变化与知识/结果漂移。该项是方法可信性的支撑性贡献，不替代 I1–I3 的效果实验。

## 6. 知识图谱与 LLM 的责任边界

| 组件 | 应承担的职责 | 不应承担的职责 |
| --- | --- | --- |
| KG | 提供灾害、产品、数据、算法、质量、恢复和证据的事实、关系、约束与候选空间 | 在代码之外隐藏不可审计的默认决策 |
| LLM | 解释开放式请求、提出候选计划、说明权衡理由 | 创造不存在的能力、绕过契约、决定质量是否通过 |
| 确定性规划/校验器 | 类型接地、依赖检查、契约验证、能力验证、fail-closed | 用固定案例答案替代全部处境化规划 |
| 执行器 | 材料化输入、调用算法、计算指标、生成产物 | 私自改变产品要求或静默接受失败结果 |

真实 LLM 的增量价值必须通过独立消融证明。在此之前，可以证明 KG 建模和 KG 驱动的确定性行为，但不得宣称真实 LLM 智能规划已经有效。

## 7. 主张边界

论文中必须区分三个证据等级：

1. **已实现**：代码路径和测试证明机制存在。
2. **已观察**：冻结案例中出现相应行为。
3. **已支持**：经过对照、重复和适当统计后，证据支持受限研究结论。

明确排除以下表述：

- 不以测试通过数作为方法优越性证据。
- 不从当前案例外推到所有城市、区域和灾种。
- 不把 memory KG 等同于已验证的图数据库性能。
- 不把 mock LLM 等同于真实 LLM 规划证据。
- 不把可运行原型表述为生产级系统。
- 不把本体类或节点数量本身表述为创新性证明。

## 8. 冻结与变更规则

1. 本章程是研究目标、RQ、创新点和主张边界的唯一 A0 权威来源。
2. KG 冻结版本一经发布不得原地覆盖；任何语义修改必须产生新版本、变更说明和迁移记录。
3. 后续任务必须标明服务于哪个目标、RQ 和证据闸门；无法映射的功能默认不进入近期关键路径。
4. A1 规范、实验协议、PPT 和历史计划与本章程冲突时，以本章程为准，并在下一次修改时消除冲突。
5. 修改核心定位、研究问题或创新点时，必须同步更新本文件、`claims-and-priorities.md`、主张—证据矩阵和文档入口。

## 9. 当前执行入口

当前顺序固定为：

1. P0-R：冻结本研究章程。
2. P0-K1：建立知识片段与迁移台账。
3. P0-K2：冻结七层 KG v1 模式层和权威机器源。
4. P0-K3：迁移灾害、任务、质量、数据源和恢复决策知识。
5. P0-K4：切断隐藏硬编码决策并建立运行消费闸门。
6. P0-K5：发布带哈希、校验报告和变更记录的 KG v1 冻结包。
7. P1 以后：独立审计、稳定性重跑、规划/治理消融和多 AOI 评价。
