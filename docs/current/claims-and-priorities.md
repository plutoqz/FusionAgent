# 论文主张、证据边界与优先级

> 状态：A0 当前权威计划
> 更新日期：2026-08-04

## 1. 双目标策略

期刊论文和硕士论文应共享同一套实验基础，但采用不同的主张宽度：

- **首篇期刊论文**以契约化灾害知识图谱为方法主体，围绕知识统一表达、KG 到运行行为的强绑定，以及规划或治理的增量价值选择 2–3 个研究问题。
- **硕士论文**覆盖七层知识模型、受约束规划、执行与质量治理、降级恢复和证据冻结，并用基线、消融、重复实验和多 AOI 形成研究闭环。

建议的首篇期刊题目方向：

> 面向灾害应急多源地理空间融合的契约化知识图谱与受约束规划

知识图谱驱动的契约治理与可复现闭环是研究主体，LLM 是其上的受约束规划机制。真实 LLM 相对固定工作流、规则策略和 KG-only 的增量价值属于完整方法的必做实验，但不预设“LLM 必然更优”；在正式对照完成前，不把“LLM 优于基线”写成结论。除非补齐真实分布式运行实验，不宣称生产部署能力。

## 3. 优先级顺序

### P0-R：研究章程冻结

目标：冻结知识图谱优先的研究对象、目标、研究问题、创新点、主张边界和术语。

退出条件：

- `docs/current/research-charter.md` 成为唯一 A0 研究章程。
- A0 状态、主张、优先级和文档入口不再与章程冲突。
- LLM、KG、确定性校验器和执行器的责任边界明确。
- 核心主张和非主张均有明确限定。

### P0-K1：知识片段盘点

目标：识别所有会改变任务编译、规划、质量验收、数据选择、降级恢复和证据生成的领域或策略知识。

退出条件：每个片段记录当前位置、知识类别、目标本体、处理方式、迁移状态和验证方法；无未分类的高风险决策常量。

### P0-K2：七层 KG v1 模式冻结

目标：形成版本化、机器可读且有人类说明的模式层和约束集合。

退出条件：七层、类、关系、属性、稳定 ID、competency questions 和完整性约束均进入版本化机器源；内存与 Neo4j 的生成入口明确引用同一知识版本。真实后端加载与行为一致性由 P0-K4 验收。

### P0-K3：决策知识迁移

目标：将灾害词汇与情景、任务语义、质量政策、源替代、修复策略和决策权重迁入 KG v1。

退出条件：运行代码只实现计算机制，不再拥有上述知识的第二份权威副本；台账中的高风险片段全部关闭。

### P0-K4：运行消费与 fail-closed 闸门

目标：证明 KG 实际决定规划与治理行为。

退出条件：修改 KG 不改代码即可改变行为；删除必需知识会明确失败；决策输出记录 KG 版本、实体 ID 和依据；禁止静默退回隐藏默认规则。

### P0-K5：KG v1 发布与独立校验

目标：发布不可静默覆盖、可审计、可复现的 KG v1 基线。

退出条件：冻结包包含 schema、实体关系、来源台账、哈希、变更记录和机器可读验证报告；篡改任一受保护文件后验证返回非零。

### P1：独立审计与篡改测试

目标：任何评审者不依赖开发者解释即可验证 Freeze C。

必须实现：

1. 单一独立验证命令。
2. 输入、prepared-input、输出和 manifest 的哈希核验。
3. `all_cases_passed=false` 时返回非零退出码。
4. 非空实验目录保护，避免覆盖旧证据。
5. 修改任一输入或输出一个字节后，验证必须失败。
6. 输出机器可读审计报告和人类可读摘要。

退出条件：原始冻结包验证成功，输入篡改测试失败，输出篡改测试失败，三类结果均有自动化测试。

### P2：稳定性和语义一致性

当前状态：已完成。Freeze C 在同一干净 commit、冻结输入和固定环境下独立重跑 3 次；语义级稳定通过，artifact 字节差异已分类，未解释差异为 0。机器报告和中文摘要统一保存在 `docs/current/evidence/p2-stability/`。

目标：证明同一干净 commit、同一冻结输入和同一协议下的结果稳定。

必须实现：

1. 至少三次独立干净重跑。
2. 比较 artifact 哈希、要素数、覆盖范围、质量指标、gap、task order 和 supersession。
3. 对时间戳、场景 ID、绝对路径等易变字段做规范化。
4. 生成语义稳定哈希和逐字段差异报告。
5. 区分字节级稳定、语义级稳定和允许波动指标。

退出条件：三次运行全部通过协议，所有不一致均被自动分类并有解释。

### P3：比较性证据

目标：把“系统工作”升级为“完整方法相对对照有可测增益”。

当前状态必须拆分：

- **P3-G 治理方向**：最小消融已完成。完整方法、无产品契约、无质量门、无降级恢复和固定优先级在同一 C02/C04/C06 manifest 与固定环境下各运行一次。机器报告和中文摘要见 `docs/current/evidence/p3-governance/`。该结果是最小方向筛查，不报告统计显著性、置信区间或跨 AOI 结论。
- **P3-P 规划方向**：正式证据未完成。`research/product-contract` 已实现 `fixed`、`kg_only`、`llm_only`、`llm_capability_kg` 和 `llm_full_contract_kg`、gold 隔离、输入顺序扰动、重复实验审计及最小端到端运行时；归并审计已确认这些成果没有直接消费当前 KG v1，也未进入共享冻结证据。应按审计分类选择性提升，不得从零重建或直接合并整个分支。

治理方向的最低比较组为：

| 组别 | 用途 |
| --- | --- |
| 无产品契约 | 测量契约约束的增量价值 |
| 无质量门 | 测量 fail-closed 治理价值 |
| 无降级恢复 | 测量 healing/policy 价值 |
| 固定优先级 | 对比上下文敏感调度 |
| 完整方法 | 目标方法 |

P3-P 正式比较固定为 `fixed workflow`、`rules-only`、`KG-only`、真实 `LLM-only`、真实 `LLM+capability KG` 和真实 `LLM+full contract KG`。其中 `rules-only` 必须与固定工作流和 KG-only 有独立实现边界；三个 LLM 组除知识上下文外使用相同模型、prompt、schema、温度和重试规则。所有组必须报告 pre-fallback validity，实验模式不得用 fallback 掩盖 LLM 调用、结构或 grounding 错误。

planning-only 核心指标至少包括计划有效率、契约满足率、禁止行为率、grounding 通过率、gap proposal precision/recall/F1、计划稳定性、时延、token 和费用。end-to-end 核心指标至少包括首次质量门通过率、错误接受率、最终契约状态正确率、降级与恢复、关键图层按时交付率、gap 声明正确率和证据完整率。质量门被禁用时，首次质量门通过率必须保持为不可用值，不能记为通过。

端到端评价不以“五类任务全部成功”为统一退出条件。对于数据缺失、质量失败和资源受限案例，正确拒绝、部分交付、degraded/provisional 状态、明确 gap 和 supersession 都可以是符合 gold 与产品契约的正确结果。

### P4：外部有效性与论文材料

当前状态必须拆分：P4-G 已完成治理链路的最小外部有效性切片；P4-P 规划机制的外部有效性尚未完成。更大样本重复和人工真值评价仍未完成。

- 已覆盖三个结构不同 AOI：Caracas 山地首都城区、Abidjan 高密度沿海都市、越南北部沿海走廊。
- C02/C04 在三个 AOI 各运行完整方法与固定优先级一次；C06 仅在 Caracas 重复，因为其他 AOI 没有独立第二道路参考源。
- 已使用 HydroLAKES/HydroRIVERS 作为外部源一致性参考，按固定源顺序抽取最多 30 个要素，以代表点或线中点在 100 m 内匹配 OSM。
- 已生成均值、样本标准差、探索性 95% CI、Cohen h、失败比例和逐案例机器记录。完整方法与固定优先级各有 7 个可比较案例；完整方法关键图层按时交付率为 6/7，固定优先级为 3/7，Cohen h 为 0.939。
- 统一材料目录为 `docs/current/evidence/p4-external-validity/`，入口见该目录的 `README.md` 和 P4 协议文档。

P4-G 结果只支持以下受限表述：在固定 memory KG、mock LLM、eager Celery、单 child worker 和冻结 commit 环境下，三 AOI 的 C02/C04 重复运行保留了计划、交付、gap 和证据记录；固定优先级在所测案例中改变了 C02 的任务顺序，并伴随较低的关键图层按时交付比例。该差异不构成显著性结论，也不能替代人工真值精度评价或真实 LLM 规划证据。C06 的质量门失败与降级恢复跨 AOI 重复仍受独立道路参考源覆盖限制。

真实 LLM 是 P3-P/RQ3 的硬性实验条件，不再归为条件性 P4。非 eager Celery 和多 worker 仍只在论文声称分布式运行或生产能力时成为硬性前置条件。Neo4j 与 memory 后端至少必须证明加载同一 KG 版本和语义内容；图数据库性能只有在相关主张下才需要评价。

P4-P 应在 P3-P 先证明实验组隔离和真实 LLM 计划可评分之后开展。它不要求把全部 planning-only 组合都做成昂贵端到端运行，而应选择能区分方法的常规、歧义、冲突、数据缺失、质量失败和渐进交付案例，验证规划决策确实改变材料化、融合、质量门和最终契约状态。

## 4. 期刊论文最小投稿包

1. 将研究问题限制为 2–3 个，每个问题有明确对照、指标和证据文件。
2. 完成 P1、P2、P3-G，并完成 P3-P 的真实 LLM 规划对照；若期刊不主张 LLM 增量，必须相应收窄题目和方法表述，不能保留受约束 LLM 规划贡献而不提供实验。
3. 至少覆盖 3 个 AOI，并说明数据选择逻辑。P4 最小切片已满足。
4. 对 C02/C04/C06 做重复实验，而不是只展示单次故事线。当前 C02/C04 已跨三 AOI 重复，C06 仍只有 Caracas，论文必须明示该缺口。
5. 给出外部有效性、构念有效性、实现偏差和数据依赖等威胁。
6. 提供冻结代码、数据清单、运行命令、环境和证据索引。

在这套实验完成前，期刊摘要应使用“在所测案例和冻结数据上观察到”之类的限定语，不使用“普遍提高”“显著增强”等宽泛表述。

## 5. 硕士论文最小闭环

冻结四项贡献：

1. 面向灾害应急数据产品的契约化七层知识图谱。
2. KG 到任务编译、规划、验证和恢复行为的强绑定机制。
3. KG 驱动的产品契约、质量门、渐进式交付与降级恢复闭环。
4. 面向知识驱动系统的可审计、可复现实验与证据冻结方法。

除共享的 P1–P4 实验外，还需完成：

- 系统架构、知识建模、调度执行、质量治理和证据管理章节。
- 实验设计、结果分析、失败案例、局限性和有效性威胁章节。
- 本体层与实体层附录，以及 JSON/CSV 机器可读附件。
- 论文级架构图、案例时间线、消融图表和结果表。
- 环境清单、运行命令、数据与代码可用性声明。

## 6. 当前调整后的执行顺序

以下顺序是本次审查后的方向调整，不是已经冻结的下一里程碑。第 1 项归并审计已经完成，结论见 `docs/current/research-branch-kg-v1-merge-audit.md`；当前停在讨论闸门，待确认实验范围、提升边界和成本后再继续。

3. 经讨论确认后，用小规模 pilot 验证六种模式隔离、gold 不泄漏、真实 LLM 有原始响应与 token 证据、`planning_source=llm` 可追踪且实验失败不被 fallback 掩盖。

5. 在规划机制成立后扩大 AOI、重复次数和人工真值评价，并统一生成论文表格、图和证据索引。
