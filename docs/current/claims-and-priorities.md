# 论文主张、证据边界与优先级

> 状态：A0 当前权威计划
> 更新日期：2026-07-28

## 1. 双目标策略

期刊论文和硕士论文应共享同一套实验基础，但采用不同的主张宽度：

- **首篇期刊论文**聚焦产品契约治理、渐进式交付、质量门和可追溯降级恢复，优先证明 C2、C3、C4 的受限版本。
- **硕士论文**可以覆盖完整系统设计、知识建模、调度执行、质量治理和证据冻结，但仍需用基线、消融、重复实验和多 AOI 形成研究闭环。

建议的首篇期刊题目方向：

> 面向多源地理空间融合的产品契约治理、渐进式交付与可追溯降级恢复

除非补齐真实 LLM 与相应消融，不把“自主智能体规划”放在首篇论文的核心主张中。除非补齐真实分布式运行实验，不宣称生产部署能力。

## 2. 主张账本

| 编号 | 主张 | 当前证据状态 | 当前可写范围 | 主要缺口 |
| --- | --- | --- | --- | --- |
| C1 | KG-grounded planning 减少无效计划 | 尚未充分证明 | 只能描述机制设计 | mock LLM、memory KG，缺少 KG/LLM 消融和计划有效率比较 |
| C2 | fail-closed governance 改善可执行成功率 | 部分支持 | C02/C06 的案例性、受限结论 | 无治理基线、样本规模、失败比例和效果量 |
| C3 | policy/healing 提高韧性 | 部分支持 | C06 的单次恢复链路 | 系统化故障注入、重复实验和恢复代价 |
| C4 | 任务特定融合质量可复现 | 当前最强 | 指定数据、AOI、commit 和协议下可复现 | 多 AOI、稳定性重复和外部参考评价 |
| C5 | 扩展契约支持未来能力 | 设计论证为主 | 可说明扩展点和契约结构 | 新数据源、任务类型或执行器的扩展实验 |

论文写作必须把“机制已实现”“案例已观察”“统计性结论已证明”分成三个等级，不得互相替代。

## 3. 优先级顺序

### P0：仓库与文档治理收口

目标：建立唯一文档入口，隔离 Freeze C 与活动开发，清除完全重复副本，归档已被替代的 PPT。

退出条件：

- Freeze C 独立 worktree 保持干净且可定位。
- 活动修改位于独立整理/研究分支，不再堆积在冻结分支。
- `docs/README.md` 能回答当前状态、权威文档和历史材料位置。
- 旧 PPT 明确标记 superseded；当前 PPT 与知识图谱导出有稳定路径。
- 文档链接检查、`git diff --check` 通过。

### P1：独立审计与篡改测试

目标：任何评审者不依赖开发者解释即可验证 Freeze C。

必须实现：

1. 单一独立验证命令。
2. 输入、prepared-input、输出和 manifest 的哈希核验。
3. `all_cases_passed=false` 时返回非零退出码。
4. 非空实验目录保护，避免覆盖旧证据。
5. 修改任一输入或输出一个字节后，验证必须失败。
6. 输出机器可读审计报告和人类可读摘要。

退出条件：原始冻结包验证成功，输入篡改测试失败，输出篡改测试失败，三类结果均有自动化测试。

### P2：稳定性和语义一致性

目标：证明同一干净 commit、同一冻结输入和同一协议下的结果稳定。

必须实现：

1. 至少三次独立干净重跑。
2. 比较 artifact 哈希、要素数、覆盖范围、质量指标、gap、task order 和 supersession。
3. 对时间戳、场景 ID、绝对路径等易变字段做规范化。
4. 生成语义稳定哈希和逐字段差异报告。
5. 区分字节级稳定、语义级稳定和允许波动指标。

退出条件：三次运行全部通过协议，所有不一致均被自动分类并有解释。

### P3：最小比较性证据

目标：把“系统工作”升级为“完整方法相对对照有可测增益”。

若主论文聚焦契约治理，最低比较组为：

| 组别 | 用途 |
| --- | --- |
| 无产品契约 | 测量契约约束的增量价值 |
| 无质量门 | 测量 fail-closed 治理价值 |
| 无降级恢复 | 测量 healing/policy 价值 |
| 固定优先级 | 对比上下文敏感调度 |
| 完整方法 | 目标方法 |

若保留 C1，再增加 `KG-only`、`LLM-only`、`LLM+capability KG` 和 `LLM+full product-contract KG`。所有组必须报告 pre-fallback validity，避免 fallback 掩盖规划错误。

核心指标至少包括：计划有效率、首次质量门通过率、最终交付成功率、降级使用率、恢复成功率、恢复代价、关键图层按时交付率、gap 声明正确率和证据完整率。

### P4：外部有效性与论文材料

目标：扩大结论适用范围，并把实验自动转化为论文材料。

- 增加 2–3 个结构不同 AOI，覆盖不同城市形态、水系密度、道路质量和数据缺失模式。
- 引入外部参考数据、专家/人工抽样或公认空间质量指标。
- 报告均值、方差或置信区间、效果量和失败比例。
- 自动生成契约判定表、输入哈希表、质量指标表、C04 时间线、C06 恢复对照表和 artifact 索引。
- 建立贡献—研究问题—实验—指标—证据对应表。

真实 Neo4j、非 eager Celery、多 worker 和真实 LLM 属于条件性 P4：只有论文声称图数据库运行价值、分布式生产运行或 LLM 规划智能时，才成为硬性前置条件。

## 4. 期刊论文最小投稿包

1. 将研究问题限制为 2–3 个，每个问题有明确对照、指标和证据文件。
2. 完成 P1、P2 和契约治理方向的最小 P3。
3. 至少覆盖 3 个 AOI，并说明数据选择逻辑。
4. 对 C02/C04/C06 做重复实验，而不是只展示单次故事线。
5. 给出外部有效性、构念有效性、实现偏差和数据依赖等威胁。
6. 提供冻结代码、数据清单、运行命令、环境和证据索引。

在这套实验完成前，期刊摘要应使用“在所测案例和冻结数据上观察到”之类的限定语，不使用“普遍提高”“显著增强”等宽泛表述。

## 5. 硕士论文最小闭环

建议冻结四项贡献：

1. 产品契约驱动的多源地理空间融合任务建模。
2. 面向渐进式交付的 provisional/supersession 机制。
3. 质量门驱动的失败暴露与降级恢复。
4. 可审计、可复现的实验与证据冻结方法。

除共享的 P1–P4 实验外，还需完成：

- 系统架构、知识建模、调度执行、质量治理和证据管理章节。
- 实验设计、结果分析、失败案例、局限性和有效性威胁章节。
- 本体层与实体层附录，以及 JSON/CSV 机器可读附件。
- 论文级架构图、案例时间线、消融图表和结果表。
- 环境清单、运行命令、数据与代码可用性声明。

## 6. 建议的执行节奏

| 阶段 | 主要产物 | 建议时间占比 |
| --- | --- | ---: |
| 仓库/文档治理 | 权威入口、归档、去重、分支职责 | 5% |
| P1 审计 | verifier、篡改测试、审计报告 | 15% |
| P2 稳定性 | 三次重跑、语义哈希、差异报告 | 20% |
| P3 比较实验 | 基线、消融、故障注入、效果量 | 30% |
| P4 多 AOI 与外部评价 | 多场景数据、参考评价、统计 | 20% |
| 写作和图表 | 章节、图表、附录、可用性声明 | 10% |

先写实验设计和结果，再反向收敛方法、引言、标题和摘要。这样可以让论文主张跟随证据，而不是让后续实验被过宽的标题绑住。
