## 1. 目标、成功标准与非目标

本轮研究任务不是“证明预设创新必然正确”，而是逐项检验：

| 主张 | 当前证据 | 下一步成功标准 |
| --- | --- | --- |
| I1：契约 KG 提供有意义的知识表达 | 已有七层模型，但无充分独立覆盖对照 | 有来源的 CQ 和反事实中，完整契约表示能回答能力目录不能回答的问题 |
| I2/RQ2：KG 实际驱动行为 | 已有限定扰动证据；当前简化 runner 仍有语义常量 | 改变 KG 条款、不改执行代码，产生预先规定的候选、校验或交付差异；缺知识 fail closed |
| I2/RQ3：知识增强改善规划 | Held-out primary 未确认优势，post-hoc 有局部信号 | 新指标和未使用确认集上报告预声明比较、效应量与簇级区间；允许无增益结果 |
| I3/RQ4：契约与恢复改善正确交付 | Contract 消融未见增益；新规划实验 E2E 为 0 | 正确拒绝、合法恢复、降级与实际 artifact 状态一致，不靠放宽质量门取得成功 |
| I4：结论可独立复核 | 历史有冻结与审计；新运行源码仍需补核 | 输入、源码、KG、计划、质量和表格可以复算并定位差异 |

系统级主结局仍为**产品契约满足度**，由图层交付、时效、质量、合法降级、gap、证据和 supersession 构成。规划正确不等于实际满足产品契约。

非目标：不扩建模板/评审平台，不重启 P0-P7，不引入独立 LLM judge 或方法冠军筛选，不堆数据源/本体节点，不重写融合算法，不宣称下游灾情研判效果。历史失败不删除，KG v1 不原地修改。

### N0-B：知识来源与协作边界

当前 `scripts/run_simplified_kg_experiment.py` 的 `V3_MISSION_PRIORITY` 与 `_build_v3_context` 将固定次序写入 `canonical_precedence`，公共 prompt 要求优先遵循它。先查对应历史输入及 KG 来源，不直接判定旧批次发生 gold 泄漏。

建立最小消费表：知识条款 -> KG/观测/代码来源 -> 可见方法 -> planner/validator 消费点 -> oracle 断言。覆盖优先级、别名、能力、质量阈值、降级许可和 evidence requirement。

重点核查：

- Contract 消融是否仍从 observation、prompt 或其他模块获得同一规则。
- 规则基线是否只处理显式 veto、AOI 歧义和静态算法映射，缺少合理的通用约束处理。
- `canonical_order` 是必要依赖还是任意全序；合法等价拓扑排序不能无理由判错。
- Planner 有真实取舍空间，还是上下文已给出唯一答案。

以上是有依据的待验证问题，不是已确认的历史性能根因。

## 4. N1：只优化证据指向的部分

| 候选优化 | 触发条件 | 最小实现与验证 | 不做什么 |
| --- | --- | --- | --- |
| 契约可计算化 | 同产物换契约不改变验收，或约束缺来源 | 复用 contract/quality 服务；对 requiredness、阈值、临时交付许可做成对干预 | 不新增 Python 政策真源 |
| KG 约束投影 | runner 常量代办约束，或消融未隔离 | 从版本化 KG/policy 投影；保存条款 ID、来源、依赖；缺失 fail closed | 不加节点或加长 prompt 追分 |
| 分离计划与实际终态 | planned/provisional 与运行状态混淆 | 区分预期产品等级与执行结果；结构化引用与理由分开 | LLM 不自评交付成功 |
| 硬约束与恢复授权 | 隐式约束没有可执行判定 | validator 查询 KG；区分不可恢复约束与可恢复缺口；保留原始计划及后续动作 | 不把实验 LLM 失败用 fallback 改成成功 |

实体、关系、属性或 policy 的语义变化需说明查询、迁移和版本影响，发布候选新版本，不原地改 KG v1。应用显式 fallback 可保留，实验分别报告 pre-fallback 与最终结果。

N1 验收是聚焦单元/合同测试与旧失败回放，不是 live capability。源码、evaluator、KG、prompt、schema、case split 冻结后才讨论真实调用授权。

## 5. E1/E2：联合设计，分别回答确认与模块贡献

### E1 指标合同

旧 `semantic_delivery` 只检查允许 decision、task order 和 delivery states，**不检查 source/algorithm grounding**，也不证明 evidence、执行或质量。新 `semantic_delivery_v2` 是待实现、待冻结候选，禁止套用旧 `38/120` 作为其结果。

建议分层：

1. Semantic：合法决策、任务集合、必要偏序、逐产品等级和必要 source/algorithm grounding；等价计划按预注册合法集合判定。
2. Safety：硬约束违反、非法源/算法、错误 unrestricted delivery；分开报告 proposal 与 validator 后实际接受。
3. Traceability：引用存在、支持对应决策、证据足够，不只是逐字复述 observation ID。
4. 严格 composite、schema 失败、成本、时延作为预声明辅助指标，报告失败构成。

先以独立领域依据冻结答案和可接受策略，再从冻结 KG 生成方法视图；oracle 不从被测 planner/投影函数生成。确认集按未使用场景组合划分，不是仅改旧 case ID、AOI 名或措辞。旧 held-out、C01-C06、H01-H09 只用于开发诊断。

### E2 三模块消融与表示检查

以同一 Full KG 为基线，去除 ontology/crosswalk、capability/grounding、contract/quality/delivery 三类信息；使用相同输入、模型、schema、预算与重复规则。分别评价身份/依赖、能力合法性、交付/质量状态，不只看 aggregate。

Contract 必须覆盖“相同观测或产物，仅契约不同”的配对：requiredness、质量阈值、deadline、provisional 许可；保留不应改变输出的负向对照。没有实际知识差异的消融不进入因果结论。

RQ1/CQ 与 RQ2 单变量消费验证随 E2 作为小型机制切片：复用现有 8 个 CQ，为未覆盖契约/恢复问题补来源和独立期望答案，不扩建平台。可计算规则由冻结 evaluator 评价，语义歧义由预声明独立人工复核处理，不使用 LLM judge 替代真值。

### 样本量、成本与统计

- 取消旧版“不得小于 240 对 / 默认 4,320 次调用”的硬要求。N0 先估计最小关注差异、场景簇数量、簇内相关和预算，不以调用次数充当独立样本。
- 若有 `P` 对 base/fault、`R` 次重复，五方法主比较的 LLM 调用为 `2 * P * R * 3`；三个消融全追加再增加同量。平铺表示增加 `2 * P * R`，确定性 KG-only 不消耗 LLM 调用。任何子集在运行前冻结。
- 成本候选包含输入/输出 token 上界、开发 pilot、允许 transport 重试、费用上限、并发、超时和停止条件；不猜价格，不默认开跑。
- 场景簇是独立设计单位，配对成员和重复属于簇内；报告逐场景结果和簇级配对区间，不把 3 次调用或多个 rubric item 当独立案例。
- 冻结主要比较顺序、多重比较处理、最小关注差异和安全阈值。多数结果与单次成功率分开；部署不投票时不能以多数通过率代表单次可靠性。
- 无不可变模型 revision 时，记录 Provider 报告身份、时间和变动风险，预先决定复现口径，不把 alias 稳定写成不可变版本。

仅对预声明、区间与安全标准通过的比较作受限结论。不要求所有比较同时显著才报告局部结果，也不从未通过推断“已证明无效”。模块无增益照实报告，不事后细分场景追显著。

## 6. E3：硬约束、恢复与正确终态

实验单元为冻结的 failure opportunity，包含应拒绝、可恢复、可降级和不可恢复机会，另设正常可交付对照，检测“全部拒绝”的伪安全。

覆盖 permission/timeout、语义或类型不兼容、质量失败、证据不足、晚到源和 supersession。先用 fixture/replay 验证；无质量门消融仅在沙箱，不实际发布不合格产物。

每个机会记录事实、KG 条款、合法动作集、原始失败、拒绝/恢复动作、代价和终态。以硬约束机会、合法恢复机会、正常机会分别作分母，报告错误接受、过度拒绝、非法恢复、正确终态和质量损失。

旧 C06 自然失败未发生仍是负结果；新预注册注入独立编号，不冒充旧 C06 自然恢复成功。样本量按故障类型和安全上界精度确定，不照搬旧“至少 120”硬门槛。零观察违规不等于风险为零。

E4 前须通过适用 deterministic 安全检查、来源闭合和产物隔离。E1 无优势不禁止 E3/E4 的安全或局部机制验证，但限制解释。

## 7. E4/E5：真实产品与质量证据

E4 在看新结果前冻结 source-closed AOI 库、场景和资源上限；优先正常多源、晚到源渐进交付、质量失败合法恢复三类，争取多个 AOI。只有一个时保留局部结果，不声称跨区域。

不只挑 Full KG 赢的案例。另用 planning 分歧驱动选例时标为探索性，单独报告，不与预选 E2E 集混池。

共享真实输入、执行器、质量门、缓存和预算；预先确定重复与计划选择规则，不挑多次 LLM 中最好一次。保存：

```text
selected -> resolved -> executed -> evaluated -> delivered
contract / source / algorithm / raw quality / adapted quality
gap / provisional / supersession / artifact hash / feature lineage
```

E5 在相同 AOI、覆盖、时间和评价条件下比较预先选定单源、简单 union、既有融合及实际交付。单源选择规则测试前冻结，不能用测试真值挑“最佳”单源。几何、属性、拓扑分别评价，新增数量配新增正确率；无独立真值时仅报告代理指标。

固定算法与输入比较编排，才能归因于协作机制；算法改变的收益单列，不算 LLM 原创融合能力。独立复核者从保存输入与源码复算主要表格和代表产物，核验异常/篡改可被发现。E4/E5 未完成时不将 planning 升级为真实交付优势。
